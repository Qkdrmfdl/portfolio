Deep dive

사람마다 됐다 안 됐다 하던 빗자루 쓸기

팀원에게 테스트를 부탁하니 저보다 훨씬 자주 실패했습니다. 쥐는 각도가 달랐기 때문입니다.

판정 기준을 손이 아니라 바닥에 맞췄습니다

고치기 전 
float h = hand.InverseTransformDirection(v).x;

쥔 손의 X축을 좌우로 읽음 → 손목을 돌리면 좌우도 같이 돈다

고친 뒤 
Vector3 h = new Vector3(v.x, 0, v.z);
if (Vector3.Dot(last, h) < -0.3f) count++;

바닥 위 수평 속도 + 꺾인 각도로 셈 → 어떻게 쥐어도 같은 값

같은 조건으로 다시 쟀습니다

팀원 · 수정 전1 / 3
팀원 · 수정 후3 / 3
본인 · 수정 전3 / 5
본인 · 수정 후5 / 5

같은 씬 · 같은 동작으로 수정 전후 비교 (2026.05.29). 작은 규모의 측정이라, 다음에는 처음부터 여러 사람 손으로 더 많이 재려고 합니다.

AI와 일한 방식

AI가 틀렸을 때, 어떻게 했나

AI의 답이 같은 자리를 맴돌면, 코드가 아니라 환경을 의심합니다.

컨트롤러 이동이 꼬여서 계속 움직이지 않던 문제가 세 번 정도 있었습니다. AI가 알려 준 대로 고쳐도 그대로였습니다. 그래서 더 고치는 대신, 깨끗한 VR 템플릿 프로젝트를 새로 열고 필요한 것만 옮겨 왔습니다.

Quest Link에서 청소 도구가 전혀 반응하지 않음
스크립트 18개 복구		예전 입력 방식(InputDevices)이 OpenXR 로더에서 기기를 못 잡음XR 로더를 Oculus로 바꿔 코드 수정 없이 동작. 다음엔 입력 방식을 처음부터 하나로 통일하기로 함
에디터에선 보이던 하이라이트가 빌드에서만 사라짐강조에 쓰던 셰이더 키워드(_EMISSION)가 빌드 과정에서 제거됨기본 색(BaseColor) 틴트를 함께 써서 빌드에서도 표시
다 치워도 청소율이 최대 50%청소율 계산이 초기 도구 5종에 고정스테이지별 대상 · 비중을 정하고 실제 쓰는 항목만으로 정규화
씬이 바뀐 직후 플레이어가 엉뚱한 위치에 섬위치를 옮긴 직후 XR 트래킹이 위치를 다시 덮어씀한 프레임 기다린 뒤 이동, 이동 중엔 CharacterController를 잠시 끔
도구나 가구 위로 올라타서 안 내려옴CharacterController의 Step Offset이 0.5m로 너무 큼0.2m로 낮춤
물통이 2개인 스테이지에서만 헹구기가 안 됨Inspector에 연결된 물통 하나만 참조지금 닿아 있는 물통을 찾아서 사용
